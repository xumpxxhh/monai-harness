# AI 高效编码实践总结

> 综合自知识库 2 篇核心文档，归档时间：2025-01-22

---

## 一、核心理念：规范驱动的 AI 协作开发

AI 辅助开发最大的瓶颈**不是 AI 的代码能力，而是上下文怎么给到它**。

- **对话式开发**：即时传递，每次会话从零开始，上下文靠口述
- **规范驱动开发**：结构化注入，把项目知识编码成 AI 能理解的数据结构，按需加载，一次写好，永久生效

目标：让 AI 从"需要反复纠正的实习生"成长为"可信赖的开发搭档"。

---

## 二、两大实践体系

### 体系 1：OpenSpec 规范层 + AI Workflows 执行层（vivo 实践）

**核心机制**：「规范 + 技能 + 钩子」
- 对 AI 的**理解、执行、校验**进行系统化约束与增强
- 关键组件：
  - **OpenSpec**：变更管理系统
  - **AI Workflows**：执行层
  - 技能（skills）：约束 AI 的分析与编码过程
  - 钩子（hooks）：在关键节点进行校验

**完整流程**：需求分析 → 方案设计 → OpenSpec 变更管理 → AI Workflows 执行 → 校验与知识回补

---

### 体系 2：知识库 + RD 流程 + 质量门禁（大淘宝技术实践）

**三阶段规划**：
```
知识库 + 工具链 → 自动化流程 → 自主协同交付
```

**第一阶段（当前重点）**：建设底座

#### 1. 分层知识库设计
| 层级 | 说明 |
|------|------|
| main | 全局业务知识 |
| applications | 应用级知识 |
| candidate | 候选知识 |
| personal | 个人经验沉淀 |
| template | 模板库 |

确保 AI 获取准确、按需加载的上下文。

#### 2. 文件化 RD 流程（Research Development）
用 Markdown 承载研发全流程，使状态可接续、可 review：
- **requirement**：需求文档
- **analysis**：需求分析与拆解
- **implementation-check**：实现校验
- **continue-prompt**：续作提示

#### 3. 前置质量门禁
在关键节点设置**人机协同 review 点**：
- PRD 验证
- 需求澄清
- 方案设计
- 避免后期高成本返工

**分工原则**：AI 负责分析实现，人聚焦关键判断。不追求 100% 全 AI 交付。

---

## 三、关键原则

### 1. 上下文是第一瓶颈
> "工具可以换，模型可以升级，底层的团队上下文和研发协议需要自己沉淀。"

值得花时间打磨的是最有团队特征、最难被通用工具替代的东西：
- 业务知识
- 应用边界
- 研发规范
- 质量门禁
- 跨应用协作方式
- 历史经验

### 2. 渐进式落地
不追求"短时间全自动化"，分阶段建设：
1. 先打底：知识库 + 流程规范
2. 再自动化：更多流程动作交给 Agent
3. 最后协同交付：开发、测试、发布、观测、回滚全链路

### 3. 人机协同
- AI 生成代码 → 人判断好坏
- AI 分析实现 → 人做关键决策
- 经验沉淀为技能 → 可跨项目复用
